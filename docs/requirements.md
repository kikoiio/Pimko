# Pimko 需求文档

## 1. 产品定位

Pimko 是一个面向"完全不会剪辑"用户的对话式短视频剪辑 agent。用户给一段口播素材，用自然语言提出需求和反馈，系统产出一条可直接发布的成片（剪辑 + 字幕 + BGM）。

### 目标用户

- **第一用户（V1 唯一用户）**：作者本人。不会剪辑，不想学时间线、关键帧、轨道等专业概念，只想"给素材 → 说哪里不对 → 拿到成片"。
- **非目标用户（V1）**：专业剪辑师、需要精细手动控制的用户。

### 核心价值主张

> 把口播视频交给 Pimko。导入素材，我先出一版草稿；你看片，用一句话说哪里不对，我改到你能直接发。

## 2. 用户故事

### US-1 导入与建草稿

**作为**不会剪辑的用户，**我想要**导入一段口播视频后自动得到第一版草稿，**以便**不用从零开始。

验收：
- 支持选择 mp4/mov/mkv/webm/m4v 文件。
- 自动完成：语音转写 → LLM 分析 → 生成时间线（保留哪些片段、剪掉哪些部分）。
- 草稿生成后 UI 显示：视频预览、片段列表、agent 说明气泡。
- 无音轨视频给出明确中文提示，不白屏。

### US-2 对话式修订

**作为**用户，**我想要**用一句中文反馈（如"开头太拖，直接进正题"）让 agent 修改成片，**以便**不懂时间线也能迭代。

验收：
- 支持多轮修订，每轮产出新 `ProjectRevision`，可追溯。
- 修订必须基于**原始转写**（事实源），不允许基于字幕反推。
- 反馈导致空时间线时，拒绝保存并保留上一版，明确告知用户。
- agent 每轮回复一句中文说明（改了什么、时长变化）。

### US-3 预览

**作为**用户，**我想要**看到草稿的实际效果（片段顺序、字幕、画面），**以便**判断哪里需要改。

验收：
- 草稿预览按时间线片段顺序播放，自动跳到下一段。
- 点击片段卡片可从该段开始播放。
- 播放中显示当前字幕。
- 手动拖动进度条后，自动跳切逻辑不失同步。
- 视频画面按原始宽高比显示，不拉伸、不变形。

### US-4 导出成片

**作为**用户，**我想要**一键导出可直接发布的 MP4，**以便**不用手工做任何后期。

验收：
- 导出包含：片段裁剪拼接、烧录字幕、（可选）BGM 混音。
- 输出分辨率跟随源视频，不强转竖屏/横屏。
- 导出过程有阶段进度提示（裁切/拼接/生成）。
- 跨片段边界的字幕按重叠区裁剪保留，不整条丢失。
- 空时间线拒绝导出，给出友好错误。

### US-5 项目恢复

**作为**用户，**我想要**重启应用后找回之前的项目继续改，**以便**不用一次做完。

验收：
- 空状态页展示最近项目列表（名称、片段数、时长）。
- 点击项目卡片恢复：源视频、最新时间线、对话上下文。

### US-6 配乐

**作为**用户，**我想要**给成片加/去 BGM，**以便**成片更有氛围。

验收：
- 可选择本地音频文件作为 BGM。
- BGM 与原声混音，导出时生效。
- 可移除 BGM。

## 3. 功能范围

### V1（当前）

| 功能 | 状态 |
|------|------|
| 导入口播视频 + 自动转写 | ✅ |
| LLM 生成剪辑草稿 | ✅ |
| 多轮对话修订 | ✅ |
| 草稿预览（跳切播放 + 字幕） | ✅ |
| 导出 MP4（剪辑 + 字幕 + BGM） | ✅ |
| 项目持久化与恢复 | ✅ |
| 导出进度 + 友好报错 | ✅ |

### V1 明确不做

- 变声 / 配音 / 语音克隆（如"改成男人的声音"）
- 转场效果（目前全部硬切）
- BGM 音量调节 UI（固定 -18dB）
- 手动时间线微调（拖动边界）
- 多素材混合剪辑（V1 单素材）
- 手机端（Android/iOS）
- 自动发布到平台

## 4. 非功能需求

### 性能

- 5 分钟以内的口播视频，草稿生成（转写 + LLM）应在 2 分钟内完成。
- 导出时间与视频时长线性相关，UI 必须有进度反馈，不允许无响应假死。

### 可靠性

- 修订永不破坏已有数据：新 revision 失败时旧 revision 完整保留。
- 空时间线不允许保存、不允许导出。
- API 错误（401/402/429/网络）映射为友好中文提示，不暴露原始 JSON。

### 数据

- 项目数据存储在本地（Electron `userData/projects`），不上传。
- API Key 只存在于本地 `.env` 或 CI secrets，绝不入仓。

## 5. 界面要求

### 布局

```
+--------------------------------------------------+
| 顶部栏：Logo | BGM | 生成成片 | 导入视频          |
+--------------------------------------------------+
| [错误/进度提示条]                                  |
+-------------------------+------------------------+
|                         |  对话流（气泡）         |
|   视频预览（居中）        |                        |
|   + 字幕叠加             |  反馈输入框 + 发送      |
|                         |                        |
+-------------------------+------------------------+
| 底部片段栏：片段卡片（编号/时间/时长）             |
+--------------------------------------------------+
```

### 交互原则

- 用户永远不需要理解"时间线""轨道""关键帧"。
- 所有长操作必须有状态反馈（建草稿中/导出中+阶段）。
- 报错说人话：告诉用户发生了什么、下一步怎么做。

## 6. 技术约束

| 项 | 约束 |
|----|------|
| 桌面框架 | Electron + React + TypeScript |
| 视频处理 | 本地 ffmpeg（系统安装） |
| 转写 | Groq Whisper `whisper-large-v3`（OpenAI 兼容 API） |
| LLM | OpenRouter 免费模型（当前 `nvidia/nemotron-3-ultra-550b-a55b:free`） |
| 配置 | `.env`（不入仓）+ CI secrets/variables |
| 测试 | GitHub Actions：typecheck + build + smoke + mock UI E2E + 真实 LLM E2E |

## 7. 验收清单

一次改动被认为"可交付"当且仅当以下全部通过：

1. `npm run typecheck` 通过。
2. CI 全绿（verify + ui + e2e-openai）。
3. 冒烟测试断言：输出分辨率 == 源视频分辨率。
4. UI E2E 断言：视频可见、无变形、片段渲染、气泡渲染。
5. 项目恢复 E2E：listProjects → restoreProject 能找回时间线。
6. 多轮修订不产生空时间线（除非用户明确要求剪空，此时拒绝并保留旧版）。
7. 空时间线导出被拒绝，错误信息友好。
8. 手动检查：导入真实口播视频 → 修订 2 轮以上 → 导出 → 成片可播放。
