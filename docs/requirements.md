# Pimko 需求文档

## 1. 产品定位

Pimko 是一个面向"完全不会剪辑"用户的对话式短视频剪辑 agent。用户给一段口播素材,用自然语言提出需求和反馈,系统产出一条可直接发布的成片(剪辑 + 字幕 + BGM)。

### 目标用户

- **第一用户(V1 唯一用户)**:作者本人。不会剪辑,不想学时间线、关键帧、轨道等专业概念,只想"给素材 → 说哪里不对 → 拿到成片"。
- **非目标用户(V1)**:专业剪辑师、需要精细手动控制的用户。

### 核心价值主张

> 把口播视频交给 Pimko。导入素材,我先出一版草稿;你看片,用一句话说哪里不对,我改到你能直接发。

## 2. 用户故事

### US-1 导入与建草稿

**作为**不会剪辑的用户,**我想要**导入一段口播视频后自动得到第一版草稿,**以便**不用从零开始。

验收:
- 支持选择 mp4/mov/mkv/webm/m4v 文件。
- 自动完成:语音转写(词级时间戳)→ 静音/停顿确定性分析 → LLM 分析 → 生成时间线(保留哪些片段、剪掉哪些部分)。
- 草稿生成后 UI 显示:视频预览、片段列表、agent 说明气泡。
- 无音轨视频给出明确中文提示,不白屏。

### US-2 对话式修订

**作为**用户,**我想要**用一句中文反馈(如"开头太拖,直接进正题"、"这段啰嗦,1.5 倍速过一下"、"去掉所有呃和嗯")让 agent 修改成片,**以便**不懂时间线也能迭代。

验收:
- 支持多轮修订,每轮产出新 `ProjectRevision`,可追溯。
- 修订必须基于**原始转写 + 词级时间戳**(事实源),不允许基于字幕反推。
- agent 可执行的剪辑操作集(V1.1 起):选段/裁边界、重排、**按段变速(0.5x–2.0x)**、**停顿压缩**、**口癖删除**;"节奏类"反馈优先用变速和停顿压缩回应,而不是只靠删除。
- 静音/停顿处理是参数化工具(阈值、最短时长、目标时长、前后边距),由确定性预剪提案、LLM 批准或整体覆盖,不让 LLM 逐个停顿判断。
- 口癖删除两类法:固定词表(呃、嗯、就是说……)机械删;语境词(然后、其实、 basically)由 LLM 判断有无语义。
- 反馈导致空时间线时,拒绝保存并保留上一版,明确告知用户。
- agent 每轮回复一句中文说明(改了什么、删了多少口癖、哪里变速、时长变化)。

### US-3 预览

**作为**用户,**我想要**看到草稿的实际效果(片段顺序、字幕、画面),**以便**判断哪里需要改。

验收:
- 草稿预览按时间线片段顺序播放,自动跳到下一段。
- 变速片段按其速度播放,字幕与音画保持同步。
- 点击片段卡片可从该段开始播放。
- 播放中显示当前字幕。
- 手动拖动进度条后,自动跳切逻辑不失同步。
- 视频画面按原始宽高比显示,不拉伸、不变形。

### US-4 导出成片

**作为**用户,**我想要**一键导出可直接发布的 MP4,**以便**不用手工做任何后期。

验收:
- 导出包含:片段裁剪拼接、变速(音频重采样,不破音)、烧录字幕、(可选)BGM 混音。
- 变速片段导出时长 = 源时长 ÷ 速度,音画同步。
- 输出分辨率跟随源视频,不强转竖屏/横屏。
- 导出过程有阶段进度提示(裁切/拼接/生成)。
- 跨片段边界的字幕按重叠区裁剪保留,不整条丢失。
- 空时间线拒绝导出,给出友好错误。

### US-5 项目恢复

**作为**用户,**我想要**重启应用后找回之前的项目继续改,**以便**不用一次做完。

验收:
- 空状态页展示最近项目列表(名称、片段数、时长)。
- 点击项目卡片恢复:源视频、最新时间线、对话上下文。

### US-6 配乐

**作为**用户,**我想要**给成片加/去 BGM,**以便**成片更有氛围。

验收:
- 可选择本地音频文件作为 BGM。
- BGM 与原声混音,导出时生效。
- 可移除 BGM。

### US-7 外部 agent 接入(M4,进阶)

**作为**会用 Claude Code 等工具的进阶用户,**我想要**通过本地 MCP 服务器驱动 Pimko 的引擎,**以便**用任意 agent 编排剪辑流程。

验收:
- 本地 MCP 暴露 `createDraft / revise / export` 与时间线读写工具,与 GUI 共享同一 `Editor` 命令层与项目状态(没有侧门)。
- agent 修改走同一套修订链(可追溯、可回退),不绕过空时间线防护。

|------|------|
| 导入口播视频 + 自动转写 | ✅ |

| 多轮对话修订(选段/边界) | ✅ |
| 草稿预览(跳切播放 + 字幕) | ✅ |
| 导出 MP4(剪辑 + 字幕 + BGM) | ✅ |
| 项目持久化与恢复 | ✅ |
| 导出进度 + 友好报错 | ✅ |

### V1.1(M4,当前)

| 功能 | 说明 |
|------|------|
| 按段变速 | `TimelineClip.speed`,0.5x–2.0x;ffmpeg `setpts/atempo`;预览与导出一致 |
| 停顿压缩 | 确定性预剪:阈值/最短时长/目标时长/边距;LLM 批准或覆盖 |
| 口癖删除 | 固定词表 + 语境词判定,词级边界,不截断相邻字词 |
| 重排语义化 | 时间线为操作列表(顺序即重排),UI 卡片可拖意会 |
| 词级转写迁移 | Groq Whisper `timestamp_granularities: ["word"]`,替换 OpenRouter omni 句级方案 |
| LLM 输出加固 | OpenRouter `require_parameters: true` + 本地 schema 校验 + 自动重试(≤2) |
| 本地 MCP 服务器 | Editor 动词 + 时间线工具,stdio JSON-RPC |

### 明确不做(V1.x)

- LLM 直接生成/执行 ffmpeg 命令(agent 只见类型化剪辑操作,不摸 ffmpeg flag)
- 变声 / 配音 / 语音克隆
- 转场导出、BGM 音量调节与撤销已纳入 M6；草稿直接播放仍以硬切近似叠化，需在成片预览确认转场效果。
- 手动时间线微调(拖动边界)
- 多素材混合剪辑(V1 单素材)
- 云端渲染(本地优先)
- 手机端(Android/iOS,远期评估)
- 自动发布到平台

## 4. 非功能需求

### 性能

- 5 分钟以内的口播视频,草稿生成(转写 + 分析 + LLM)应在 2 分钟内完成。
- 导出时间与视频时长线性相关,UI 必须有进度反馈,不允许无响应假死。

### 可靠性

- 修订永不破坏已有数据:新 revision 失败时旧 revision 完整保留。
- LLM 输出一律过本地 schema 校验;非法 JSON 自动重试(至多 2 次),仍失败则保留上一版并以中文报错,不暴露原始响应。
- 静音/停顿分析为确定性算法:同一输入必然同一输出,可单测。
- 空时间线不允许保存、不允许导出。
- API 错误(401/402/429/网络)映射为友好中文提示,不暴露原始 JSON。

### 数据

- 项目数据存储在本地(Electron `userData/projects`),不上传。
- API Key 只存在于本地 `.env` 或 CI secrets,绝不入仓。

## 5. 界面要求

### 布局

```
+--------------------------------------------------+
| 顶部栏:Logo | BGM | 生成成片 | 导入视频          |
+--------------------------------------------------+
| [错误/进度提示条]                                  |
+-------------------------+------------------------+
|                         |  对话流(气泡)         |
|   视频预览(居中)        |                        |
|   + 字幕叠加             |  反馈输入框 + 发送      |
|                         |                        |
+-------------------------+------------------------+
| 底部片段栏:片段卡片(编号/时间/时长/变速标记)    |
+--------------------------------------------------+
```

### 交互原则

- 用户永远不需要理解"时间线""轨道""关键帧"。
- 变速、去口癖等操作以片段卡片标记 + agent 说明呈现,用户用自然语言控制。
- 所有长操作必须有状态反馈(建草稿中/导出中+阶段)。
- 报错说人话:告诉用户发生了什么、下一步怎么做。

## 6. 技术约束

| 项 | 约束 |
|----|------|
| 桌面框架 | Electron + React + TypeScript(2026-10 调研确认主流路线,不变更) |
| 视频处理 | 随包 ffmpeg/ffprobe 静态二进制(extraResources),开发态回退 ffmpeg-static/系统 PATH;用户无需安装 | |
| 转写 | Groq Whisper `whisper-large-v3`(OpenAI 兼容 API),词级时间戳 |
| LLM | OpenRouter 免费模型 + `require_parameters: true` + 客户端 schema 校验 |
| 编排 | 手写 fetch + JSON schema,不引入 LangChain |
| 对外接口 | 本地 MCP 服务器(与 GUI 共享同一 `Editor` 命令层) |
| 配置 | `.env`(不入仓)+ CI secrets/variables |
| 测试 | GitHub Actions:typecheck + build + smoke + mock UI E2E + 真实 LLM E2E |

### 参考实现与复用规则

依据 `docs/research/2026-10-24-agentic-video-editing-prior-art.md`:

- **可直接搬代码**(保留版权声明):video-use(MIT;打包转写格式、切点淡入淡出、自检流程)、auto-editor(Unlicense;静音检测算法与参数)、kinocut(Apache-2.0;工具校验、receipts 模式)、revideo / editly(MIT;TS 侧 ffmpeg 驱动模式)。
- **只读设计,不抄代码**:OpenChatCut、OpenMontage(AGPL 传染);kerf(PolyForm NC);CutClaw、vidpipe(无 license)。
- 架构三原则(优胜项目共性):GUI 与 agent 共用同一命令层;agent 不直接接触 ffmpeg;编辑是可审阅、可撤销的提案。

## 7. 验收清单

一次改动被认为"可交付"当且仅当以下全部通过:

1. `npm run typecheck` 通过。
2. CI 全绿(verify + ui + e2e-openai)。
3. 冒烟测试断言:输出分辨率 == 源视频分辨率。
4. UI E2E 断言:视频可见、无变形、片段渲染、气泡渲染。
5. 项目恢复 E2E:listProjects → restoreProject 能找回时间线。
6. 多轮修订不产生空时间线(除非用户明确要求剪空,此时拒绝并保留旧版)。
7. 空时间线导出被拒绝,错误信息友好。
8. 手动检查:导入真实口播视频 → 修订 2 轮以上 → 导出 → 成片可播放。
9. 变速片段导出后音画同步,时长 = 源时长 ÷ 速度。
10. 静音预剪对同一输入确定性输出;LLM 可批准或整体覆盖。
11. 口癖删除落在词边界,不截断相邻字词。
12. LLM 返回非法 JSON 时自动重试,最终失败保留上一版并友好报错。
13. MCP 冒烟:外部 MCP 客户端完成 createDraft → revise → export 闭环。

- 真实模型验收：中文口播连续修改、导出效果检查；当前免费模型限流，未通过完整验收。
- 效果预览的缓存、修改失效、UI 播放及与导出的解码音画哈希一致性，已在 d7040f7 云端通过。
