# Pimko 项目意图

> 更新：2026-10-29。依据真实使用反馈与 [参考实现研究](research/2026-10-29-reference-implementations.md)。本文只定义产品意图、边界与验收；架构见 [剪辑架构设计](design/2026-10-29-editing-architecture.md)，执行顺序见 [分阶段计划](plans/2026-10-29-editing-core-rebuild.md)。

## 1. 产品是什么

Pimko 是一个面向"完全不会剪辑"用户的对话式短视频剪辑 agent。用户导入素材，用中文说想要什么、哪里不对，Pimko 完成初剪、字幕、配乐和导出。

**它不是**：专业时间线编辑器、模板生成器、自动发布工具，也不是"只能剪口播"的垂直工具。

**它的承诺**：用户只需要判断成片能不能发，并用一句话描述问题；不需要理解轨道、关键帧、切点或 ffmpeg。

## 2. 用户与任务

**第一用户**：作者本人。不会剪辑，想稳定做出可以发布的短视频。

Pimko 要完成的不是单一内容类型，而是三类典型任务：

| 任务 | 素材 | 用户想要的结果 |
|---|---|---|
| 口播/访谈清理 | 一段或多段说话视频 | 去掉口癖、停顿和废条，保留完整句子，字幕准确 |
| 旅行/蒙太奇 | 一组镜头、音乐 | 按镜头和节拍组接，节奏不拖，画面不跳 |
| 教程/录屏 | 屏幕录制、操作演示 | 保留步骤和关键操作，文字可读，废话剪掉 |

三类任务共用同一套对话、修订和导出体验；区别在分析器与质量检查，不在产品概念。

## 3. 核心循环

```text
导入素材
  → 理解素材（语音/镜头/节拍/响度）
  → 确定性初剪
  → agent 提案
  → 预览
  → 一句反馈
  → 修订
  → 导出
```

每一轮都要让用户看到：改了什么、为什么改、成片时长怎么变、切点是否有问题。

## 4. 产品原则

1. **用户判断结果，不操作时间线。** UI 呈现故事板、片段卡片、预览和 diff；不要求用户拖轨道。
2. **先确定性基线，再让模型决策。** 静音、镜头、节拍边界由算法给出；LLM 只做受约束的语义选择与修改。
3. **内容类型自适应。** 有语音用词级转写；没有语音用镜头/节拍/画面变化；不把口播规则硬套到蒙太奇。
4. **质量必须可见。** 每个切点有证据（时间、前后文、检查结果、截图/波形），不用"导出成功"冒充"可以发布"。
5. **失败保守。** 非法计划、空时间线、渲染失败、质量不通过都保留上一版；不覆盖旧成片。
6. **本地优先。** 素材、项目、密钥留在本机；除用户配置的模型/转写服务外不上传。

## 5. 范围

### 5.1 首个可用版本

单素材、任意内容类型，打通完整链路：

- 一段口播、访谈、教程、旅行片段或录屏。
- 自动判断可用信号；语音素材走词级转写，无语音素材走镜头/节拍/响度。
- 1–3 轮自然语言反馈，预览与导出。
- 首期验证优先口播：词级时间戳提供最严格的客观切点标准；它只是验证切片，不是产品边界。

### 5.2 之后扩展

- 多素材：多段口播、访谈、旅行素材合并。
- 蒙太奇/活动视频：按镜头、节拍、叙事顺序组接。
- 教程/录屏：按步骤组织，保留操作节点与可读文字。
- B-roll/补充画面：先检索再插入。
- 轻量画面包装：标题、花字、转场；不做完整动效设计工具。

### 5.3 不做

- 专业手动时间线、关键帧、多轨精修。
- 完整 motion graphics / 网页动画创作工具（openfilm 式 `film.html` 不作为核心）。
- 云端渲染、手机端、自动发布。
- 在质量基线建立前继续增加 LLM 功能。

## 6. 质量契约

一条成片只有同时满足以下条件才算"可交付"：

1. **不破坏语义单元**：语音切点落在词边界；无语音素材不切断稳定镜头或关键动作；切点前后保留 30–200ms 呼吸边距。
2. **音频边界无爆音**：每个片段边界有约 30ms 的音频淡入/淡出。
3. **节奏自然**：删除/压缩的是静音、无效停顿或重复节拍，不是句内换气或镜头内关键动作；变速不造成突兀跳变。
4. **文字正确**：有语音时字幕按输出时间轴生成，变速、重排、裁剪后仍对齐，且最后叠加不被遮挡；无语音时不强行生成字幕。
5. **画面连续**：切点不出现黑帧、跳帧、明显闪烁；转场只在适合的素材上使用。
6. **时长可解释**：输出时长与保留的片段/词/节拍可对上，误差在 100ms 量级。
7. **每个切点有自检**：渲染后在实际输出的切点附近抽帧、测波形、查字幕遮挡；最多自动修 3 轮，仍失败则明确告知。
8. **修改可解释、失败不污染**：每轮展示增/删/移/变速 diff 与一句中文说明；非法计划、空时间线、渲染失败都保留上一版。

## 7. 内容类型判定

| 内容类型 | 主要信号 | 关键质量点 |
|---|---|---|
| 口播/访谈 | 词级转写、停顿、说话人 | 不切词、口癖/停顿处理、字幕同步 |
| 旅行/蒙太奇 | 镜头边界、运动、音乐节拍 | 镜头完整、节奏与节拍、画面连续 |
| 教程/录屏 | 步骤、操作节点、画面文字 | 步骤完整、文字可读、关键操作不被剪 |
| 混合素材 | 以上组合 | 不把一种类型的规则硬套到另一种 |

同一套 `Editor`、修订链和文档模型服务所有类型；分析器与质量检查可插拔。

## 8. 验收

一次改动只有在以下全部通过后才算可交付：

1. `npm run typecheck`、`npm run check:editing`、`npm run check:fixtures`、`npm run smoke`、`npm run smoke:mcp` 通过。
2. 固定基准集（中文口播、英文口播、旅行/蒙太奇、教程/录屏）各完成导入 → 建稿 → 修订 → 导出。
3. 每个成片通过第 6 节对应的质量契约；至少 2/3 达到"愿意直接发布"的主观标准。
4. 每个成片有切点自检报告，列出时间、前后文、检查结果与证据路径。
5. 修改前后的 A/B 对比可复现；失败版本保留在 `.tmp`，不覆盖旧修订。
6. 真实模型路径与 mock 路径都跑通；真实模型失败时给出可操作的中文错误。

## 9. 约束

- Electron + React + TypeScript；本地 ffmpeg/ffprobe；数据只存本地。
- agent 不直接拼 ffmpeg 命令；所有编辑经同一套命令层与修订链。
- GUI 与 MCP 共用同一 `Editor`，没有旁路。
- 模型/转写密钥只在本地 `.env` 或 CI secrets，不入库。
- 不同内容类型共用一套工程文档与修订模型；分析器可插拔。
