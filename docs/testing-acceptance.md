# Pimko 当前版本人工验收用例

本轮只验收已经存在的能力，不开发新功能。先完成第 2 节的首次体验，再分批执行完整用例。本文共 84 个独立用例 ID，矩阵内的每个输入还需分别记录结果。

编写依据为 `7b1351e0e46258fc89bba37dca4607bd7a561f1f` 的源码，以及 [测试素材](testing-fixtures.md) 和 [需求文档](requirements.md)。实际执行时必须记录自己的版本。需求文档中的里程碑和历史 CI 结果不能替代本轮验收。

**本文没有执行任何用例。** 所有常规用例初始状态为“待测”。需要尚未提供的受控响应或专门环境的用例标为“阻塞”。缺少素材、API 授权或可运行版本时，也应记录“阻塞”和具体原因。不得把“模型回复改好了”“存在输出文件”或“以前 CI 通过”记为本轮通过。

## 1. 准备一次可复查的验收

### 1.1 确认当前产品边界

| 项目 | 当前操作入口和边界 | 验收时的处理 |
|---|---|---|
| 输入 | 一次选择一个视频，文件过滤器支持 mp4、mov、mkv、webm、m4v | 再次导入会创建另一项目，不是把第二份素材拼进当前成片 |
| 修改 | 输入“剪辑反馈”，点击“发送”或按 Enter | 没有手动裁边界、拖卡片重排的界面；重排要用对话 |
| 草稿预览 | 直接播放源视频，按片段跳切，字幕由界面叠加 | 时间轴刻度是源视频时间；叠化只做硬切近似，配乐需在实际渲染中听 |
| 效果预览 | 点击“查看实际效果”，本地渲染当前修订并缓存 | 包含剪辑、变速、烧录字幕、叠化、配乐，无需选择导出路径 |
| 成片预览 | “生成成片”并保存后出现 | 播放实际导出的文件，播放器速度应为 1，不再套一遍片段变速或字幕 |
| 配乐 | “添加配乐”“移除配乐”和“轻”“标准”“响” | 三档分别为 -24、-18、-12 dB；连续值只在命令接口提供，没有界面滑杆 |
| 字幕 | 用对话调整大中小、上中下、加粗或简洁、显示或隐藏 | 当前没有文字逐字编辑、字体选择、任意坐标与字号输入界面 |
| 撤销 | “撤销上一步”，支持连续回退 | 没有重做入口。回到初稿后再次撤销可以提示“已经是第一版” |
| 恢复 | 重启后在“最近项目”选择项目 | 恢复最新修订；当前界面会重建一条恢复提示，不重放旧聊天气泡。模型接收原始转写和当前时间线，不接收完整聊天记录 |
| 缓存 | 效果预览按项目 ID 和 revision ID 缓存 | 同版重复查看复用，改版后界面失效；撤销也产生新 revision，不能要求复用旧 ID 的文件。没有缓存管理界面 |
| 尚未实现 | 多素材拼接、补充画面、画幅裁切、配音、自动发布 | 测试边界告知和已有项目是否保全，不能记为这些功能通过 |

`src/renderer/src/App.tsx` 是按钮、禁用状态和预览模式的依据。`scripts/e2e-ui.ts` 提供自动化行为参考，但不证明本轮人工体验、语义质量、错误分支或并发安全已经通过。

### 1.2 分清 mock 和真实接口

| 模式 | 可用于验收 | 不可据此判定 |
|---|---|---|
| M：mock | 界面流程、存储、撤销、配乐、渲染；关键词反馈“开头太拖”“第一段 N 倍速”“添加叠化转场”；字幕关键词 | 真实语音识别、内容正确性、语义删句、指定段重排、语境口癖、空计划拒绝 |
| R：真实接口 | 真实转写、中文和英文理解、按内容删改、重排、多轮约束保持 | 一次成功不能证明其它供应商、模型或全部材料通过 |
| I：受控故障或命令接口 | 精确制造空 clips、非法模型结果、存储失败、并发调用 | 普通 mock 的关键词逻辑不能替代响应注入；界面没有相应入口时，必须先由协调者提供专用测试环境 |

mock 转写按约 4 秒一段生成占位中文，与真实音轨无关。mock 初稿也会用静音图做确定性预剪。mock 修改的优先级为字幕、开头裁剪、第一段速度、叠化；一次只发一种操作。即使写“第二段 2 倍速”，mock 仍修改第一段。不能把这条行为当作模型理解了段号。

mock 字幕示例可用“字幕调大并移到顶部”“字幕标准大小”“字幕移到中间”“字幕简洁”“隐藏字幕”“显示字幕”。“删除全部”“把最后一段放开头”不会在普通 mock 中实现。mock 的超范围速度会夹到 0.5 至 2，不能用它验证真实模型对非法速度的拒绝策略。

真实接口适配器选择 `PIMKO_LLM_PROVIDER=openai`，可接 OpenAI 兼容供应商。记录剪辑与转写各自的供应商、base URL 的公开域名和模型名。只记录密钥“已配置”，不要复制值。缺少密钥导致配置回退到 mock 时，真实用例必须记为阻塞，不能继续充当真实结果。配置选择、重启和联网均由实际执行者另行安排，本文不启动应用或发送请求。

后文“BGM 材料”指 `supportMedia` 中的自生成音频：`bgm-2s.wav/mp3/m4a/aac/ogg/flac` 和 `bgm-30s.wav`（每个扩展名对应独立文件）。覆盖六种格式、短配乐循环和长配乐截断。“词边界材料”指 manifest 标明原话、目标词和源时间区间的口播条目。“编号材料”指能从画面或声音识别源时间与顺序的条目。

### 1.4 保存基线与证据

1. 使用专门的验收项目和输出目录，避免覆盖用户已有项目、原视频或成片。导出路径记为 `<验收输出目录>/<用例ID>-<轮次>.mp4`，将占位符替换为执行者选择的实际绝对路径。
2. 每次破坏性输入前，记录当前项目 ID、revision ID、片段的源区间、顺序、速度、转场、字幕外观和 BGM。本文把这份记录称为“上一版基线”。
3. 如需精确判断版本，执行者可只读查看 Electron `userData/projects/<projectId>/<revisionId>.json`。先确认本次应用实际的 userData 路径，不猜目录、不修改正式项目文件。效果缓存位于同一 userData 的 `previews`，缩略图在 `thumbnails`。
4. 以实际音画验证编辑。将“代理说明”和“实际发生的修改”分开记录。若转写错误导致编辑错误，分别记录转写问题和编辑结果。
5. 记录开始、结束、等待提示和失败时间。草稿生成超过 2 分钟时记录耗时与供应商状况，不把静默等待无限延长。渲染耗时没有固定秒数门槛；检查界面是否有状态并最终成功或报错，单独记录等待上限。

执行自动化 GUI、渲染、生成素材或大规模测试时，重型操作优先云端免费 CI；本轮已获授权使用本仓库 GitHub Actions 生成合成测试材料和执行检查，沿用该授权即可，不重复请求。新增云服务、权限或非公开素材上传才需另行说明并获许可。本机仅在云端无法覆盖时兜底，遵循全局内存、`/tmp`、显存规则：检查 MemAvailable 和 PSI，本机 GUI 至少有 4G 可用内存，Electron 加 `--disable-gpu`，自动化另遵循 Wayland/X11 设置，一次一个实例。渲染临时文件改道根文件系统。本轮文件生成和自动渲染不在本机执行；用户日常手动体验按自己的安排进行。

## 4. 多轮编辑、删除与语义边界

## 5. 变速与时间口径

本节 5 例。先选无叠化项目。对源区间 `[a,b]`、速度 `s`，段时长为 `(b-a)/s`；整条时长为各段之和减去叠化重叠之和。卡片只保留一位小数，精确比较以修订数据为准。

| ID | 模式、材料或前置 | 手工步骤 | 通过条件 |
|---|---|---|---|
| SP-01 | M、R；F1 或编号材料；首段有有效音轨 | 发“第一段 0.5 倍速，其他段不变”；分别点卡片试听和实际渲染播放；核对时长 | 首段标 0.5x，时长约为源区间两倍；其它段速度不变；效果预览和导出以播放器 1x 播放，声音没有再次慢放、明显变调或与画面标记错位 |
| SP-02 | M、R；SP-01 状态 | 发“第一段 1 倍速，其他段不变”；核对卡片、实际渲染与导出 | 首段恢复原区间时长，2x 或 0.5x 标识消失；源区间和其它设置不回到初稿；声音与对应字幕同步 |
| SP-03 | M、R；同一项目 | 发“第一段 2 倍速，其他段不变”；播放首段到第二段；导出核对 | 首段时长为源区间一半，第二段恢复自己的速度；输出不是首段 4 倍速；词边界、音画同步无累计漂移 |
| SP-04 | R；至少三段的编号或词边界材料 | 分三轮将第 1、2、3 段分别设为 0.5、1、2 倍速；重排一次；加一次叠化；比较字幕及末尾标记 | 不同段保留各自速度；重排不串段；总时长按公式减叠化；中段与末尾字幕跟随实际语音。当前渲染自检容差为 `max(0.6秒, 预计时长×6%)`，通过自检仍需人工确认无可感知错位 |
| SP-05 | M 对照、R 主验；保存基线 | 分别请求“第一段 0 倍速”“第一段 0.1 倍速”“第一段 3 倍速”；每次恢复基线后重试 | R 拒绝或把实际速度限制在 0.5 至 2，并准确说明结果；不得保存 0 或越界速度。M 将数值夹到范围内，应记录实际值，不能充当非法模型计划校验通过；精确非法计划另见 FA-06 |

## 14. 分批完成并记录结果
